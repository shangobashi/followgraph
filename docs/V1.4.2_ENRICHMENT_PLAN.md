# FollowGraph v1.4.2 Beta Enrichment Plan

Problem observed in live use: scan completed acceptably fast, but enrichment succeeded for only 38 of 160 profiles. That is about 24%, which makes inactive-account review and unfollow safety unusable.

Goal: keep the v1.4 scanner speed improvements while raising enrichment success toward the 90% target.

## Root Causes Addressed

- API resolver was too dependent on hardcoded GraphQL feature flags.
- API operation discovery could give up too early if X scripts were not ready.
- Helper profile pages did not install the page-world API capture hook before resolving activity.
- Helper DOM fallback waited only a few seconds before returning `unknown`.
- Many helper tabs could load simultaneously, increasing the odds of X throttling or incomplete profile renders.
- Unknown results were treated as final even when likely transient.

## Implemented Fixes

### 1. Captured GraphQL request templates

`xapi.ts` now preserves captured or performance-discovered operation variables and features. User-specific values such as `screen_name` and `userId` are overwritten, but X-provided feature flags are retained.

### 2. Retryable operation discovery

Bearer-token and operation discovery no longer permanently fail after a too-early attempt. The resolver can retry after scripts/resources are available.

### 3. Profile-page API capture and replay

Helper profile pages now install the same page-world GraphQL capture hook used by scans. The fallback can replay recent GraphQL resource URLs and resolve from captured user payloads before relying on DOM text.

### 4. More patient DOM fallback

The helper waits longer, clicks visible retry buttons, nudges the timeline scroll, and checks captured payloads again before declaring a profile unknown.

### 5. Lower helper-tab pressure

Default enrichment helper concurrency is reduced from 15-20 workers to 6-10 workers. This favors success rate over raw tab throughput and should reduce X throttling/loading failures.

### 6. One retry for transient unknowns

A profile that resolves to `unknown` is requeued once after other profiles. Only the second unknown becomes a final failed enrichment.

## New Verification Gate

Reports now include:

- `enrichmentAttempted`
- `enrichmentSucceeded`
- `enrichmentFailed`
- `enrichmentSuccessRate`

`scripts/acceptance-gate.mjs` fails if `enrichmentSuccessRate` is below 90% when the report includes enrichment metrics.

## Non-Goals

- Do not make unfollow less strict. Unfollow still requires enriched accounts with `inactiveOver30`.
- Do not remove API fallback paths. X changes too often for a single resolver.
- Do not restore high helper-tab concurrency until live evidence shows success remains above 90%.
